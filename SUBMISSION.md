# Hackathon submission — copy/paste for the Google Form

**Project name:** Frontdesk — real-time AI phone receptionist (100% AssemblyAI)

**Category:** Build with the TTS API **+** Bug bounty / security findings

**One-liner:** A voice receptionist you can actually interrupt — and, while building it, we found that AssemblyAI's
own quickstart ships a browser token it calls "single-use" that is actually reusable, multi-session, and cross-product
on production (responsibly disclosed, with repros).

**Headline security finding (security/REPORT.md, scorecard at security/scorecard.html):** AssemblyAI's Voice Agent
starter (`assembly init voice-agent`) places a browser token in a client-visible WebSocket URL and justifies it in its
own code and page copy as "a short-lived, single-use token" / "one-time token". On production that token is: (A) not
single-use — reusable for its full 600 s life, and it opened **5 concurrent sessions**; (B) not product-scoped — a
`streaming/v3/token` drives paid TTS and the $4.50/hr Voice Agent, and an `agents/v1/token` drives STT and TTS; (C)
uncapped — one scraped token = up to 10 min of concurrent paid work across STT+TTS+Voice Agent+LLM, billed to the
account. Every developer who copies the quickstart inherits this. Fair play: TTL is enforced and capped at 600 s, and
errors don't leak internals — both credited. Runnable reproductions in security/probes/; disclosure email in
security/disclosure.txt.

**Built with AssemblyAI's agent tooling:** the second engine (Voice Agent API with real tool calls) was written by a coding agent running the official AssemblyAI skill, grounded in code generated by the AssemblyAI CLI (`assembly init voice-agent`, `assembly agent --show-code`). I also tried AssemblyAI's own coding agent (`assembly live`), but it can't take a turn on a hackathon key (the only model rejects tools). That's documented as finding #9. Details: BUILT_WITH_ASSEMBLYAI_AGENT.md

**Description (short):**
Two switchable engines: a hand-built pipeline and AssemblyAI's Voice Agent API. Frontdesk answers calls for a dental clinic, a pizzeria and a Paris hotel. Every piece runs on one AssemblyAI key:
Universal-Streaming for the caller, LLM Gateway for the brain, and the new Streaming TTS for the voice.
LLM tokens are streamed sentence-by-sentence into TTS (`Generate`+`Flush`), so caller-stops-to-first-audio is
~0.6–1.3 s. Barge-in cancels TTS, discards stale flushes until `Cancelled`, flushes the browser buffer and tells the LLM
exactly what the caller heard (from `WordBoundaries` vs. the playback clock). Captions light up word-by-word from
`WordBoundaries`. Actions (bookings/orders/reservations) are executed live with guardrails against small-model
hallucinations; totals come from a till, not the LLM. Also: 8 kHz μ-law phone-line mode and automatic language
detection with voice switching (fr/es/de/it/pt). A headless simulator has a second TTS voice phone the agent for
end-to-end tests.

**TTS API findings (see FINDINGS.md, with repro scripts):**
1. (Security) STT temporary tokens are accepted by the TTS service — token scope isn't product-bound.
2. (Security) Temporary tokens are multi-use: one token opened concurrent sessions until expiry.
3. `Cancel` doesn't abort in-flight/queued flushes — audio keeps streaming (bad for barge-in, still billed).
4. 5-session concurrency cap counts already-closed sessions for 30–60 s → reconnect patterns lock you out.
5. SSML/markup is spoken literally. 6. Voices are language-bound and undiscoverable (one voice per non-English language).
7. `Cancelled.audio_duration_seconds` is always 0. 8. Full reverse-engineered protocol reference.
9. AssemblyAI's coding agent (`assembly live`) can't run on hackathon keys.
10-12. Voice Agent API: caller turns silently swallowed right after `reply.started`; a sample rate that's accepted then crashes the session; odd time pronunciation and event ordering.
